# `Field` 가 자식에 주입하지 못할 때 경고한다

**날짜:** 2026-09-03
**대상:** v0.5.6
**요청:** `dashboard-shell` 의 `common-ui-v0.5.5-회신-답.md` — 새 요청 1번

## 문제

`Field` 는 `if (isValidElement(children))` 안에서만 자식에 `id` 를 주입한다
(`src/react/controls/Field.tsx:44`). 게이트가 거짓이면 **주입 블록 전체가 조용히
건너뛰어진다** — `<label htmlFor>` 은 자기 `useId()` 값을 받고 자식은 아무것도
못 받아 라벨이 아무것도 가리키지 않는다.

**소비자가 계측해서 원인을 찾았다.** Next.js 의 RSC 페이로드가 자식을 평범한
엘리먼트가 아니라 `React.lazy` 참조로 넘기는 배선이 있었다.

```
깨지는 쪽 : isValidElement=false   $$typeof=Symbol(react.lazy)
정상인 쪽 : isValidElement=true    $$typeof=Symbol(react.transitional.element)
```

lazy 로 감싸일지는 **청크 경계**가 정하므로 조건이 재현하기 까다롭고,
**`next dev` 에서만** 났다(프로덕션 빌드는 정상). 그래서 **테스트도 프로덕션
빌드도 못 잡는다.** 지금은 감지 수단이 하나도 없어, 하이드레이션 불일치를 본
사람이 `Field` 를 의심할 이유조차 없다.

## 측정 — 범위를 정하기 위해 잰 것

`react-dom` 18.3.1 + jsdom 스크래치 프로젝트에서 `v0.5.5` 설치본으로 쟀다.

### `lazy` 는 판별자가 아니다

| 자식 | 라벨이 이어지나 |
|---|---|
| `lazy` + 내부가 프롭 **전달** | ✅ |
| `lazy` + 내부가 프롭 **무시** | ❌ |
| **일반 컴포넌트 + 프롭 무시** | ❌ |

즉 진짜 판별자는 "자식이 주입받은 프롭을 labelable 요소까지 전달하는가" 이고,
그것은 **렌더 시점에 알 수 없다.** 초기 조사에서 "lazy 엘리먼트도 깨진다" 는
관찰을 했는데, 그것은 프로브가 프롭을 무시하는 컴포넌트를 썼기 때문이었다 —
철회한다.

### 결과 검사는 마커 경로에서 거짓 양성이다

이펙트 시점에 `document.getElementById(label.htmlFor)` 를 보는 방식도 재봤다.

| 경우 | 이펙트 시점 target |
|---|---|
| 네이티브 정상 | `INPUT` |
| 프롭 무시 래퍼 | `null` (잡힌다) |
| `children` 이 lazy 객체 | `null` (잡힌다) |
| **커스텀 엘리먼트(마커 경로)** | **`null` — 거짓 양성** |

안쪽 `<input>` 의 `id` 는 Lit 이 마이크로태스크에서 쓰므로 이펙트 시점에는 아직
없다. **⑥(`ns-sidebar` 경고)에서 설계를 되돌리게 만든 바로 그 함정이다.**

## 결정

**`!isValidElement(children)` 하나만 본다.**

- 렌더 시점에 확정된다. 타이밍 의존이 없다
- 거짓 양성이 없다
- **소비자가 실제로 부딪힌 경우를 정확히 덮는다**

**프롭을 무시하는 래퍼는 잡지 않는다.** 정적으로 알 수 없고, 그것은 `Field` 만의
문제가 아니라 React 에서 일반적인 성질이라 이 라이브러리가 감지할 계약이 아니다.
넓히려면 결과 검사가 필요한데, 그 대가가 방금 실측으로 위험하다고 확인한
타이밍 의존이다 — ⑥에서 같은 이유로 설계를 되돌렸다.

### 코드

`src/react/controls/Field.tsx` 의 게이트에 `else` 를 붙인다.

메시지에 **`label` 값을 넣는다** — 한 화면에 `Field` 가 여럿일 때 어느 것인지
알려야 한다. 형식은 이 저장소의 다른 경고와 같이 `[ns-field]` 접두사를 쓴다.

**중복 억제는 ⑥과 같은 형태다** — `useRef` 가드 + `useEffect(…, [])`. 렌더
본문에서 `console.warn` 하면 StrictMode 이중 렌더에 두 번 찍히는 것을 ⑥에서
실측했다(2 → 1). 가드는 **인스턴스당 1회**다.

**타이밍 의존은 생기지 않는다.** 판정은 렌더 시점 값으로 하고, 이펙트는 *언제
찍을지*만 정한다.

## 검증

테스트 러너는 없다(설계 결정). ⑥ 검증에 쓴 `react-dom` 스크래치 하네스를
재사용한다 — **그 하네스는 이번 세션에서 실제로 물었다**(변이를 넣자 1 → 0).

| 자식 | 경고 |
|---|---|
| 평범한 엘리먼트 | 0 |
| 커스텀 엘리먼트(`NsMultiSelect`) | 0 |
| `lazy` 객체 그 자체 | 1 |
| StrictMode 에서 같은 것 | 1 |

**검사를 실패시켜 본다** — 경고를 지우면 셋째가 1 → 0 이 되어야 한다.

## 범위 밖

**`cloneElement` 대신 context 로 바꾸는 것**(회신의 선택 요청 2번)은 하지 않는다.
공개 API 가 바뀌고 `Input`·`Textarea`·`Select` 와 마커 경로 전부를 건드려야 한다.
경고가 먼저 나가고, 그 뒤에도 이 부류가 반복되면 그때 다시 본다.
