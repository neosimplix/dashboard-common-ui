# `Field` 경고가 RSC 경로를 놓친다 — 서버 렌더 자리를 더한다

**날짜:** 2026-09-03
**대상:** v0.5.7
**요청:** `dashboard-shell` 의 `common-ui-v0.5.6-회신-답.md`

## 문제

`v0.5.6` 에 넣은 경고가 **정작 그 요청을 만든 사고에서 뜨지 않는다.**

소비자가 `next dev` 에서 그 배선을 다시 띄우고 브라우저 콘솔을 `ns-field` 로 걸렀다 —
**0건.** 서버 터미널도 0건이다(하이드레이션 오류만 2건).

이유는 구현이 아니라 **자리**다. 하이드레이션 오류의 트리 덤프가 비대칭을 그대로 보여준다.

```
<Bn name="id" type="email" …>
  <input
+   id="_R_q9bn5rlb_"     ← 클라이언트는 주입했다
-   id={null}             ← 서버는 안 했다
```

**게이트가 거짓인 것은 서버 패스뿐이다.** RSC 페이로드가 `lazy` 로 도착하는 것은 서버
렌더 순간이고, 클라이언트에서는 이미 풀려 평범한 엘리먼트가 온다. 그런데 경고는
`useEffect` 에 있고 이펙트는 클라이언트에서만 돈다 — **그때 게이트는 이미 참이다.**
서버 패스에는 이펙트가 없다. 그래서 양쪽 다 조용하다.

**⑥(`ns-sidebar`)에서 이펙트로 옮긴 판단은 그 문제에서는 맞았다** — 거기 조건은
"소비자가 프롭을 줬나" 라 클라이언트 렌더 시점에 확정된다. **②-b 는 조건이 서버
전용이라 같은 자리가 정확히 틀린 자리가 된다.** 둘이 같은 종류로 보였지만 아니었다.

## 측정

`react-dom` 18.3.1 로 직접 쟀다.

### 서버 렌더에는 이펙트가 없고 StrictMode 중복도 없다

| | 렌더 본문 | 이펙트 |
|---|---|---|
| `renderToString` | 1회 | **0회** |
| `renderToString` + StrictMode | **1회** | 0회 |

**이펙트로 옮긴 원래 이유(StrictMode 이중 찍힘)가 서버에서는 적용되지 않는다.**

### 클라이언트 쪽 네 경우는 지금 경고가 잡고 있다

| 자식 | 경고 | 라벨이 이어짐 |
|---|---|---|
| 자식 둘(배열) | 1 | ❌ |
| 문자열 | 1 | ❌ |
| `null` | 1 | ❌ |
| `undefined` | 1 | ❌ |

**넷 다 라벨이 실제로 끊겨 있다** — 거짓 양성이 아니다. 그러므로 서버 전용으로
**옮기면** 이 넷이 조용해진다. 순손실이다.

## 결정

**옮기지 않고 자리를 하나 더 둔다.**

```
게이트가 거짓 && typeof window === "undefined"  →  렌더 본문에서 경고   (추가)
게이트가 거짓 && 그 외                           →  이펙트에서 경고     (유지)
```

- 두 조건은 **환경으로 배타적**이라 같은 렌더에서 겹치지 않는다
- SSR 앱에서 양쪽 다 거짓인 경우(`{null}` 등)만 둘 다 나는데, **다른 콘솔**
  (터미널 vs 브라우저)이라 소음이 아니고 오히려 유용하다
- 서버 경고는 `next dev` **터미널**에 찍힌다 — 개발자가 브라우저 콘솔을 안 보고
  있어도 로그에 남고 **CI 로도 잡을 수 있다.** ②-b 의 가장 큰 문제가 "감지 수단이
  없다" 였는데 이 자리가 그것을 실제로 없앤다

### 문구를 나눈다

**진단이 다르므로 처방도 다르다.**

- **서버(렌더 본문)** — RSC 경로 전용이다. 자식이 서버에서 만들어져 `lazy` 로
  도착했다는 것과, 자식을 클라이언트에서 만들거나 그 파일에 `"use client"` 를 붙이라는
  처방
- **클라이언트(이펙트)** — 자식이 단일 React 엘리먼트가 아니라는 것. 배열·문자열·
  `null` 이 여기 걸린다

문구를 하나로 공유하면, RSC 사고를 만난 사람이 "자식을 엘리먼트 하나로" 를 읽고
엉뚱한 것을 의심한다.

### 받아들이는 대가

**렌더 본문에서 `console.warn` 하는 것은 순수성 위반이다.** 서버 렌더는 한 번만
돌아 실질 피해가 없지만 원칙을 어기는 것은 맞다. 대안이 없다 — 이펙트는 서버에서
안 돌고 서버 전용 훅도 없다. 근거를 주석과 `docs/gotchas.md` 에 남긴다.

## 문서

**`guide.html` 의 `Field` 절이 지금 거짓을 말한다.**

> `v0.5.6` 부터는 경고가 난다. … 위 증상을 다시 만나면 이제 `Field` 를 의심할
> 근거가 생긴 것이다.

**그 증상이 경고가 안 뜨던 경우다.** 코드를 고치면 이 문장이 참이 되지만
**어느 콘솔에 뜨는지를 명시해야 한다** — RSC 경로는 브라우저가 아니라 **dev 서버
터미널**이다. 브라우저에서 찾으면 못 찾는다.

그리고 같은 절의 이 문장도 이제 갱신된다.

> `v0.5.6` 이전에는 자동화된 잡을 수단도 없었다.

`v0.5.7` 부터는 있다 — 서버 경고가 터미널에 남으므로 CI 로 잡을 수 있다.

**Chrome 이 스스로 잡아 주는 것도 적는다.** 소비자가 찾아준 것이다.

```
Incorrect use of <label for=FORM_ELEMENT>
```

하이드레이션 오류와 이것이 같이 뜨면 `Field` 를 의심하라는 신호다. `v0.5.7` 전까지는
그것이 유일한 감지 경로였다.

**`docs/gotchas.md`** — 왜 자리가 둘인지. 같은 결함이 환경마다 다른 자리에서
나타나므로 감지도 두 자리가 필요하다는 것, 그리고 **⑥에서 배운 교훈을 여기 그대로
적용했다가 틀렸다**는 것. 조건이 클라이언트에서 확정되는가 서버에서 확정되는가가
자리를 가르고, 그 구분 없이 "이펙트가 안전하다" 를 일반화한 것이 이번 실수다.

## 검증

`react-dom` 스크래치 하네스를 확장한다.

**서버 경로** — `renderToString` 으로 렌더하고 경고 수를 센다.

| 자식 | 서버 경고 |
|---|---|
| 평범한 엘리먼트 | 0 |
| `{lazy 객체}` | **1** |
| StrictMode 로 감싼 같은 것 | **1** |

**클라이언트 경로** — 기존 네 경우가 그대로 유지되는지(회귀 없음).

**검사를 실패시켜 본다** — 서버 경고를 지우면 서버 표의 둘째·셋째가 1 → 0 이 되어야
한다. 클라이언트 표는 안 변해야 한다(두 자리가 독립임을 보인다).

## 범위 밖

**context 전환**은 이번에도 하지 않는다. 소비자가 보류에 동의했고, 그쪽은 예방
검사(`Field` 사용처 열넷이 전부 `"use client"`)로 실질적으로 막고 있다.
