# 릴리스 전에 사람이 봐야 하는 것

`.claude/rules/verification.md` 가 이 저장소의 회귀 확인 수단을 둘로 못박는다 — `npm run check` 와 `index.html` 육안 확인. 이 파일이 담는 것은 **두 범주**다.

- **A — `index.html` 육안 확인이 볼 목록.** 두 번째 수단은 볼 것의 목록이 있어야 작동한다.
- **B — 두 수단 **어느 쪽도** 닿지 않는 것.** `index.html` 에는 React 도 Tailwind 도 번들러도 없어서, 여기서는 재현 자체가 불가능하고 소비자 프로젝트가 있어야 확인된다. **B 는 `index.html` 확인의 일부가 아니라 세 번째 범주다.**

## 이 파일을 다루는 법

- **살아 있는 목록이다. 릴리스가 나가면 비운다.** 항목의 가치는 "바뀌었는데 아직 아무도 눈으로 안 봤다" 하나뿐이라, 확인이 끝난 항목은 소음이다. 낡은 항목이 쌓인 목록은 없는 것보다 나쁘다 — 훑고 넘기는 습관을 만들고, 그 습관은 다음 사이클의 진짜 새 항목까지 함께 넘긴다.
- **누적 로그로 만들지 않는다. 그 일은 git 이 이미 한다.** `git log -p docs/pending-human-checks.md` 가 사이클마다 무엇을 봐야 했는지를 그대로 준다. 파일 안에 이력을 또 쌓으면 중복이고, 둘이 어긋날 때 낡는 쪽은 언제나 파일 안이다.
- **비우는 법: 아래 `## 범위` · `## B` · `## A` 세 절을 통째로 지우고 `## 대기 없음` 한 줄을 남긴다.** `## 범위` 를 함께 지우는 것이 중요하다 — 그 절은 아래 목록이 무엇을 덮는지 설명하는 것이라, 목록 없이 남으면 없는 내용을 주장하는 문장이 된다. 파일 자체를 지우거나 완전히 비우지도 않는다. 그러면 "지금 정말 대기가 없다" 와 "아무도 안 채웠다" 가 구분되지 않는다.
- **비우는 시점은 태그를 자르기 전이다.** `.claude/skills/releasing/SKILL.md` 가 `## 실행` 앞에서 이 파일을 가리킨다. 남아 있는 항목은 확인되지 않은 항목이고, 태그는 되돌릴 수 없다.
- 항목을 더할 때는 **무엇을 보나** 와 **무엇이 잘못된 것인가** 를 함께 적는다. 하나만 있으면 보는 사람이 판정할 수 없고, 판정할 수 없으면 정상인 변화를 결함으로 신고하는 쪽으로 기운다. 아래 A 항목의 상당수는 그 오인을 미리 막으려고 있다.
- **B 를 A 보다 앞에 둔다.** A 는 `index.html` 을 열면 어차피 눈에 걸리지만, B 는 여기 적혀 있지 않으면 존재조차 알 수 없다.

---

## 범위

**`v0.5.0` 태그가 나간 뒤의 핫픽스다.** 사용자가 접히는 사이드바에서 글자가 찌그러지며 사라지는 것을 직접 보고 신고했다. 원인 둘을 함께 고쳤다.

- **`ns-sidebar.styles.ts` — `nav` 에 `min-width: var(--ns-sidebar-width)` 를 되살렸다.** 0.5.0 개발 중에 지웠던 것을 다시 세웠다. 지운 이유였던 "`ns-sidebar { width: … }` override 가 깨진다" 는 더 이상 사실이 아니다 — 그 뒤에 `:host` 가 (다른 이유로) 얻은 양방향 `overflow: hidden` 이 넓어진 `nav` 를 호스트 경계에서 잘라내므로 더는 삐져나오지 않는다. 남는 대가는 하나다 — 토큰보다 좁은 override 를 주면 내용은 여전히 토큰 폭 기준으로 배치된 채 그 좁은 폭에서 잘린다.
- **`ns-nav-group.styles.ts` — `.heading` 에 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis` 를 더했다.** collapsible 헤딩(`<button class="heading"><span class="row"><span class="text">…`)은 실제로 넘치는 지점이 `.heading` 자신이 아니라 `.text` 이므로, 같은 세 선언과 `flex: 1; min-width: 0` 을 `.text` 에도 따로 뒀다.

**`dist/` 가 바뀐다.** 둘 다 컴포넌트 shadow 스타일이라 빌드 산출물에 그대로 반영된다.

## A. 이 저장소의 `index.html` 에서 확인한다

### A-1. 접힐 때 글자가 찌그러지지 않고 그대로 잘리는가

**이 릴리스의 핵심 증거다.** `min-width` 가 없던 동안 사용자가 실제로 본 결함 — 글자 사이 간격이 줄고 아이콘·라벨이 서로 밀리며 찌그러지다 사라지는 것 — 이 사라졌는지 본다. 200ms 는 맨눈으로 판정하기 짧으므로 devtools 의 CPU 스로틀링(4배 이상)이나 화면 녹화 후 프레임 재생으로 늘려서 본다.

- **볼 것:** 문서 셸의 헤더 토글로 좌측 사이드바를 닫는다. ① 전이 내내 글자 크기·자간·줄 높이가 변하지 않는다 ② 항목 라벨이 오른쪽부터 잘려 사라질 뿐 글자 모양이 찌그러지지 않는다 ③ 그룹 헤딩도 같다 — 여러 줄로 접히거나 글자가 겹치는 프레임이 없다 ④ 전이가 끝나면(폭 0) 사이드바가 통째로 사라진다
- **무엇이 잘못된 것인가:** 폭이 줄어드는 동안 글자 사이 간격이 눈에 띄게 좁아진다 · 라벨이나 헤딩이 여러 줄로 접혔다 펴진다 · 아이콘과 글자가 겹치거나 밀리는 프레임이 보인다(모두 `min-width` 가 다시 빠졌거나 `.heading`/`.text` 의 `white-space: nowrap` 이 안 걸린 증상이다)
- **릴리스 때 할 일:** 결함이면 이번 릴리스를 막는다. 소비자에게 나가는 코드다

### A-2. 열릴 때도 같은가

**A-1 은 닫는 방향만 본다.** 여는 방향의 전이도 같은 CSS 규칙(`min-width`·`nowrap`)을 타므로 독립적으로 확인한다 — 한쪽만 고치고 다른 쪽을 안 보는 실수를 여기서 잡는다.

- **볼 것:** 닫힌 사이드바를 헤더 토글로 연다. ① 폭이 늘어나는 내내 글자 크기·자간이 변하지 않는다 ② 처음에는 아무것도 안 보이다가(폭이 아직 좁아 `overflow: hidden` 에 잘려 있음) 폭이 늘수록 오른쪽부터 글자가 드러난다 ③ 찌그러지거나 겹치는 프레임이 없다
- **무엇이 잘못된 것인가:** A-1 과 같은 증상이 여는 방향에서만 나타난다(닫는 쪽만 고치고 여는 쪽을 놓친 것) · 전이 초반에 글자가 짧게 찌그러져 보였다가 정상으로 돌아온다
- **릴리스 때 할 일:** 결함이면 이번 릴리스를 막는다. 소비자에게 나가는 코드다

### A-3. 사이드바보다 긴 그룹 헤딩이 줄바꿈 대신 말줄임표로 잘리는가

**`.heading` 에 `white-space: nowrap` 이 없던 동안의 결함이다.** 평상시(전이와 무관하게)에도 헤딩이 사이드바 폭보다 길면 줄바꿈해 아래 항목을 밀어냈다. 콘솔로 만든다.

```js
// 비collapsible(div.heading) — 「관리」
document.querySelector("#nav-group-nested-demo ns-nav-group[heading='관리']").setAttribute("heading", "아주 길게 늘어난 그룹 제목으로 줄바꿈 여부를 확인하는 문장")
// collapsible(button.heading > .row > .text) — 「사용자」
document.querySelector("#nav-group-nested-demo ns-nav-group[heading='사용자']").setAttribute("heading", "아주 길게 늘어난 그룹 제목으로 줄바꿈 여부를 확인하는 문장")
```

- **볼 것:** ① 헤딩이 **한 줄**로 남고 오른쪽 끝이 말줄임표(`…`)로 잘린다 ② 헤딩 줄의 높이가 다른 헤딩·항목과 같다(두 줄로 안 늘어난다) ③ 그 아래 목록의 위치가 밀리지 않는다 ④ collapsible 헤딩(caret 이 있는 것)과 비collapsible 헤딩(caret 이 없는 것) 양쪽에서 같다 — 마크업이 `<button><span class="row"><span class="text">` 와 `<div>` 로 서로 다르므로 한쪽만 보면 안 잡히는 회귀가 있을 수 있다
- **무엇이 잘못된 것인가:** 헤딩이 여러 줄로 접혀 아래 목록을 밀어낸다(`white-space: nowrap` 이 안 걸린 것) · 말줄임표 없이 글자가 그냥 잘려 있다(`text-overflow: ellipsis` 가 안 걸린 것) · collapsible 쪽에서만 잘못된다(`.text` 규칙이 안 걸린 것 — `.heading` 자신은 이 마크업에서 넘치지 않으므로 `.heading` 만 고치면 이 경로가 조용히 빠진다)
- **릴리스 때 할 일:** 결함이면 이번 릴리스를 막는다. 콘솔로 만든 상태는 새로고침하면 사라진다

### A-4. `ns-sidebar { width: … }` override 가 토큰보다 좁을 때 잘리기만 하고 삐져나오지 않는가

**`min-width` 를 되살린 대가를 확인하는 항목이다.** README·index.html 이 이제 "override 는 토큰보다 좁지 않을 때만 안전하다" 고 적는다 — 좁게 준 경우 내용이 잘리는 것 자체는 **정상**이고, 확인할 것은 잘린 `nav` 가 호스트 밖으로 삐져나오지 않는 것이다. 콘솔로 만든다.

```js
document.getElementById("docs-nav").style.width = "12rem"
```

- **볼 것:** ① 사이드바의 오른쪽 경계선이 **12rem(192px) 자리**에 있다(더 넓은 자리에 있지 않다) ② 항목 라벨과 그룹 헤딩이 12rem 안에서 필요한 만큼 말줄임표로 줄어든다 ③ 본문이 12rem 부터 시작한다 ④ devtools 로 `ns-sidebar` 의 shadow 안 `<nav>` 자신의 계산된 폭을 읽으면 `min-width` 때문에 **240px(15rem)** 로 나온다 — 이것은 정상이다. 확인할 것은 그 240px 짜리 `nav` 가 192px 짜리 호스트를 벗어나 화면에 삐져나오지 않는가다 — `nav` 의 오른쪽 끝(240px 지점)이 화면에서 보이지 않고 호스트 경계(192px)에서 잘려야 한다
- **무엇이 잘못된 것인가:** 사이드바 오른쪽 경계선이 12rem 을 넘어 15rem 근처에 있다(잘리지 않고 삐져나온 것 — `:host` 의 `overflow: hidden` 이 깨진 회귀다) · 본문이 12rem 이 아니라 15rem 부터 시작한다
- **릴리스 때 할 일:** 결함이면 이번 릴리스를 막는다. 콘솔로 만든 상태는 새로고침하면 사라진다
