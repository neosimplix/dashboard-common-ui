# 릴리스 전에 사람이 봐야 하는 것

`.claude/rules/verification.md` 가 이 저장소의 회귀 확인 수단을 둘로 못박는다 — `npm run check` 와 `index.html` 육안 확인. 이 파일이 담는 것은 **두 범주**다.

- **A — `index.html` 육안 확인이 볼 목록.** 두 번째 수단은 볼 것의 목록이 있어야 작동한다.
- **B — 두 수단 **어느 쪽도** 닿지 않는 것.** `index.html` 에는 React 도 Tailwind 도 번들러도 없어서, 여기서는 재현 자체가 불가능하고 소비자 프로젝트가 있어야 확인된다. **B 는 `index.html` 확인의 일부가 아니라 세 번째 범주다.**

## 이 파일을 다루는 법

- **살아 있는 목록이다. 릴리스가 나가면 비운다.** 항목의 가치는 "바뀌었는데 아직 아무도 눈으로 안 봤다" 하나뿐이라, 확인이 끝난 항목은 소음이다. 낡은 항목이 쌓인 목록은 없는 것보다 나쁘다 — 훑고 넘기는 습관을 만들고, 그 습관은 다음 사이클의 진짜 새 항목까지 함께 넘긴다.
- **누적 로그로 만들지 않는다. 그 일은 git 이 이미 한다.** `git log -p docs/pending-human-checks.md` 가 사이클마다 무엇을 봐야 했는지를 그대로 준다. 파일 안에 이력을 또 쌓으면 중복이고, 둘이 어긋날 때 낡는 쪽은 언제나 파일 안이다.
- **비우는 법: 아래 `## 범위` · `## B` · `## A` 세 절을 통째로 지우고 `## 대기 없음` 한 줄을 남긴다.** `## 범위` 를 함께 지우는 것이 중요하다 — 그 절은 아래 목록이 무엇을 덮는지 설명하는 것이라, 목록 없이 남으면 없는 내용을 주장하는 문장이 된다. 파일 자체를 지우거나 완전히 비우지도 않는다. 그러면 "지금 정말 대기가 없다" 와 "아무도 안 채웠다" 가 구분되지 않는다.
- **비우는 시점은 태그를 자르기 전이다.** `.claude/skills/releasing/SKILL.md` 가 `## 실행` 앞에서 이 파일을 가리킨다. 남아 있는 항목은 확인되지 않은 항목이고, 태그는 되돌릴 수 없다.
- 항목을 더할 때는 **무엇을 보나** 와 **무엇이 잘못된 것인가** 를 함께 적는다. 하나만 있으면 보는 사람이 판정할 수 없고, 판정할 수 없으면 정상인 변화를 결함으로 신고하는 쪽으로 기운다. 아래 A 항목의 상당수는 그 오인을 미리 막으려고 있다.
- **B 를 A 보다 앞에 둔다.** A 는 `index.html` 을 열면 어차피 눈에 걸리지만, B 는 여기 적혀 있지 않으면 존재조차 알 수 없다.

## 범위

**`v0.4.0` 이후의 변경이다.** `v0.2.5..v0.4.0` 을 덮던 목록(B-1…B-5 · A-1…A-27)은 `v0.4.0` 이 나간 뒤 비웠다. 무엇이 있었는지는 `git log -p docs/pending-human-checks.md` 가 갖고 있다.

이번 사이클이 넣은 것은 셋이다.

- **문서 정리.** 소비자가 저자 한 사람뿐이라 태그별 이관 안내를 `README.md` 와 `index.html` 양쪽에서 걷어냈다. 이것만 있었다면 `dist/` 는 바뀌지 않았다.
- **Safari 전용 결함 하나.** 대화상자 본문이 WebKit 에서 높이 0 으로 붕괴해 한 줄짜리 문장에도 스크롤 막대가 생겼다. `.body` 를 `flex: 1` 에서 `flex: 1 1 auto` 로 바꿔 고쳤고, 근거는 `docs/gotchas.md` 에 있다. **`dist/` 가 바뀐다.**
- **세로 정렬 두 곳.** `ns-toast` 의 닫기 버튼이 첫 줄 글자와 세로 중심을 맞추고, `ns-dialog` 의 footer 가 우측이 아니라 가운데로 정렬한다. **후자는 배치의 자리를 옮긴 변경이라 파급이 넓다** — footer 슬롯에 들어온 것이 곧 flex 항목이어야 정렬과 `gap` 이 걸리므로, `confirm.ts` 와 `index.html` 데모가 버튼을 감싸던 `<div>` 를 걷어냈고 React `Dialog` shim 은 걷어낼 수 없는 래퍼에 `display: contents` 를 줬다. **`dist/` 가 바뀐다.**

## B. 이 저장소에서 재현할 수 없다

### B-1. React `Dialog` 의 footer 버튼이 가운데로 오고 사이가 벌어지는가

`index.html` 에는 React 가 없어 shim 이 만드는 래퍼(`<div slot="footer" style="display: contents">`)를 여기서는 볼 수 없다. **`npm run check` 가 초록인 것은 이 항목에 대해 아무 증거도 아니다** — 타입만 맞으면 통과하고, `display: contents` 가 실제로 래퍼를 비켜서게 하는지는 렌더해야 안다.

- **볼 것:** `footer={<><Button variant="outline" size="sm">취소</Button><Button size="sm">확인</Button></>}` 로 대화상자를 열어 ① 두 버튼 묶음이 하단 **가운데**에 있다 ② 두 버튼 사이가 `--ns-space-2`(0.5rem)만큼 벌어져 있다 ③ 버튼 하나만 넘겼을 때(`docs/consumer-example.tsx` 가 그 모양이다)도 가운데다
- **잘못된 것:** 버튼 묶음이 오른쪽에 붙어 있다 · 두 버튼이 서로 맞닿아 한 덩어리로 보인다 · 버튼이 footer 폭 전체로 늘어난다(`display: contents` 가 먹지 않고 래퍼가 flex 항목으로 남은 것)
- **Tailwind 소비자에서 함께 본다:** preflight 는 `display` 를 건드리지 않으므로 영향이 없어야 한다. 그래도 위 셋을 그대로 다시 본다

## A. 이 저장소의 `index.html` 에서 확인한다

### A-1. 이관 절을 걷어낸 자리가 매끄럽게 이어지는가

지운 곳이 다섯이라 **끊긴 자리나 죽은 링크가 남기 쉽다.** 지운 것 자체는 되돌아볼 필요가 없고, 남은 문서가 그 자리에서 자연스럽게 이어지는지만 본다.

- **볼 것:** ① 설치 절의 업그레이드 안내가 **한 문단**으로 줄었고 그 안에 링크가 없다 ② 사이드바 「시작하기」 그룹에 **설치 · 환경별 연동** 둘만 있다 ③ 「Tailwind 를 쓰면 레이어 순서를 선언해야 한다」 절 다음이 곧바로 「환경별 연동」이다 ④ 「디자인 토큰」 절의 액센트 설명 두 벌(선·링 / 채움면)과 코드 블록, 그 아래 스와치 격자가 그대로다 ⑤ `nsToast` 절이 「위치」 표 → 「인자」 → 「JS」 → 「주의」로 끊김 없이 이어진다
- **잘못된 것:** 사이드바 항목을 눌렀는데 페이지 맨 위로 튄다(지운 앵커를 가리키는 링크가 남은 것) · 제목만 있고 본문이 없는 절이 보인다 · 절 사이 여백이 다른 곳과 눈에 띄게 다르다
- **릴리스 때 할 일:** 없다. 이 항목은 문서만 고쳤다

### A-2. 토스트의 닫기 버튼이 글자와 세로 중심이 같은가

`nsToast` 절의 버튼으로 네 tone 을 모두 띄운다. 기준은 **이미 맞아 있던 좌측 점**이다 — 점과 닫기 아이콘과 첫 줄 글자, 셋의 세로 중심이 한 줄에 있어야 한다.

- **볼 것:** ① 한 줄짜리 토스트에서 `×` 아이콘의 중심이 글자의 중심과 같은 높이다 ② `neutral`(점이 없는 것)에서도 같다 ③ **긴 메시지로 두 줄 이상이 될 때** 점과 `×` 가 **첫 줄**의 중심에 있다(가운데 줄이 아니다 — 여러 줄에서 블록 전체의 가운데로 오면 그것이 잘못된 것이다) ④ 토스트 상자의 높이가 예전보다 늘거나 줄지 않았다 ⑤ 닫기 버튼에 마우스를 올렸을 때 생기는 사각 배경이 토스트 위아래 경계선을 넘지 않는다
- **잘못된 것:** `×` 가 글자보다 아래에 있다(고치기 전 상태다) · `×` 가 상자 위 테두리에 닿거나 밖으로 나간다 · hover 배경이 상자 밖으로 삐져나온다 · 네 자리(`top-center`·`bottom-center`·`top-right`·`bottom-right`) 중 어디선가만 다르다
- **릴리스 때 할 일:** 없다 — `scripts/release.mjs` 가 태그 커밋에서 `dist/` 를 새로 빌드한다. 다만 이 항목은 **소비자에게 나가는 코드**라, 문서만 고친 A-1 과 달리 태그가 실제 동작을 바꾼다

### A-3. 대화상자 footer 버튼이 하단 가운데에 있고 사이가 벌어지는가

`ns-dialog` 데모(비제어)와 `nsAlert` · `nsConfirm` · `nsConfirm (danger)` 버튼 넷을 모두 눌러 본다. **`nsConfirm` 두 개가 이 변경의 핵심 증거다** — 고치기 전에는 취소와 확인이 서로 맞붙어 있었다.

- **볼 것:** ① 데모의 취소 · 승인이 하단 **가운데**에 있고 사이가 `--ns-space-2` 만큼 벌어져 있다 ② `nsAlert` 의 확인 버튼 하나가 가운데다 ③ `nsConfirm` 의 취소 · 확인이 가운데이고 **서로 붙어 있지 않다** ④ `nsConfirm (danger)` 도 같고, 열리자마자 **취소**에 포커스 링이 있다 ⑤ 취소를 눌러 닫으면 포커스가 열었던 버튼으로 돌아온다 ⑥ footer 아래·좌우 여백이 예전과 같다
- **잘못된 것:** 버튼이 오른쪽에 붙어 있다 · 두 버튼이 맞닿아 있다 · 취소와 확인의 **순서가 뒤바뀌었다**(문서 순서로 배정되므로 취소가 왼쪽이어야 한다) · danger 에서 초기 포커스가 확인에 간다(콘솔에 `[ns-confirm]` 경고가 함께 뜬다) · footer 영역이 내용 없이 남아 있다
- **릴리스 때 할 일:** 없다 — `scripts/release.mjs` 가 태그 커밋에서 `dist/` 를 새로 빌드한다. 다만 이 항목은 **소비자에게 나가는 코드**라, 문서만 고친 A-1 과 달리 태그가 실제 동작을 바꾼다

### A-4. Safari 에서 대화상자 본문에 스크롤 막대가 없는가

**이 항목만 Chrome 이 아니라 Safari 로 본다.** 고치기 전 결함이 WebKit 에서만 나타났고, Chrome 에서는 처음부터 정상으로 보였다 — 여기서 Chrome 만 보면 아무것도 검증되지 않는다.

- **볼 것:** Safari 로 `index.html` 을 열고 ① `ns-dialog` 데모 ② `nsAlert` ③ `nsConfirm` 을 각각 띄워, 한 줄짜리 본문 오른쪽에 **스크롤 막대가 없다** ④ 본문 글자가 잘리지 않고 위아래 여백이 Chrome 과 같아 보인다
- **긴 본문도 함께 본다:** 본문이 화면을 넘길 만큼 긴 대화상자에서는 **본문만** 스크롤되고 제목 줄과 버튼 줄은 제자리에 고정돼야 한다. 그 스크롤은 정상이다 — 없어져야 하는 것은 짧은 본문의 스크롤이다
- **잘못된 것:** 짧은 문장인데 스크롤 막대가 있다(고치기 전 상태다) · 본문 영역이 패딩만 남고 글자가 안 보인다 · 긴 본문에서 대화상자 전체가 화면 밖으로 넘어간다
- **릴리스 때 할 일:** 없다 — `scripts/release.mjs` 가 태그 커밋에서 `dist/` 를 새로 빌드한다. 다만 이 항목은 **소비자에게 나가는 코드**라, 문서만 고친 A-1 과 달리 태그가 실제 동작을 바꾼다
