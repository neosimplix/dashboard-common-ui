목차

버전 기록

태그마다 무엇이 바뀌었는지 · 왜 그랬는지 · 이주 코드를 담는다. 새 버전이 위에 온다.

README.md 의 릴리스 표는 태그와 한 줄 요약만 갖고, 그보다 긴 것은 전부 이 페이지에 있다. 같은 사실을 두 곳에 적지 않는다 — 두 곳에 함께 있는 것은 태그 목록 하나이고, 그 둘이 어긋나지 않는지는 scripts/check-controls.mjs 가 양방향으로 대조한다.

dist/ 가 바뀌었는지를 태그마다 적는 이유. 안 바뀐 릴리스는 설치해도 화면이 그대로다. 그런데 소비자가 그것을 알 방법은 태그를 둘 받아 diff -rq 하는 것밖에 없다 — 버전 번호만 보고는 산출물이 그대로인지 알 수 없으므로 여기 적는다. 문서만 고친 릴리스도 태그를 다시 잘라야 하는 까닭은 guide.html 과 이 파일이 package.json 의 files 에 들어 있어 패키지와 함께 배포되기 때문이다.

v0.4.0 이하는 여기에 없다. 이 기록은 README.md 의 릴리스 표와 같은 범위이고, 그 표는 v0.5.0 부터 담는다. 지운 절이 다루던 태그는 git 에서 여전히 설치할 수 있다 — 문서에서만 뺐다.

v0.5.4

dist/ 변경 · breaking 하나

소비자 보고를 반영했다. dashboard-shell 이 프리미티브 17개를 이 패키지로 이관하면서 실측으로 찾아낸 것들이고, 네 가지가 이 태그에 들어갔다. 마크업을 고쳐야 하는 변경은 없다.

직접 넘긴 aria-invalid 가 컴포넌트의 invalid 프롭을 더 이상 무력화하지 않는다. Input·Textarea· Select 셋 다 지역 계산이 나머지 props 를 펴는 앞에 있어서, 소비자가 aria-invalid 를 직접 넘기면 {...rest} 가 그 값을 덮어썼다. 이제 지역 계산을 편 뒤에 합치므로 소비자가 준 값이 살아남는다.

Field 안의 동작은 이 태그로 바뀌지 않는다. Field 는 오류가 있을 때 aria-invalid: true 하나만 주입하고, 뒤에서 합쳐도 true 는 여전히 true 다 — 오류가 있으면 항상 이긴다. <Field error><Textarea invalid={false} /></Field> 가 invalid 로 보이는 것과, Field 안에서 invalid 를 넘겨도 차이가 없는 것 — 소비자가 보고한 두 증상 — 은 이 릴리스 뒤에도 그대로다. 오류가 있는 필드의 컨트롤은 invalid 여야 한다는 것이 애초에 의도한 동작이라 고칠 결함이 아니었다.

Field 와 ns-multi-select 를 함께 쓸 수 있다. 커스텀 엘리먼트는 labelable 이 아니라 호스트에 id 를 얹어도 label for 가 닿지 않았다. Field 가 이제 안쪽 컨트롤의 프로퍼티(inputId·inputDescribedby·inputInvalid)로 내려보내므로 라벨과 오류 문구가 실제로 이어진다.

소비자가 호스트에 직접 준 id 는 안전하다 — Field 가 그 값을 더 이상 읽지 않고 안쪽 input 에는 스스로 만든 id 를 쓴다. 다만 소비자가 inputId 를 직접 넘기고 있었다면 Field 가 그것을 덮어쓴다. 그리고 @lit/react 가 반응형 프로퍼티를 useLayoutEffect 안에서 설정하고 ns-multi-select 의 업데이트 자체는 Lit 이 그 뒤 비동기로 돌리므로, 렌더 직후 동기 조회 (getByLabelText 등)는 아직 안 붙은 라벨을 보고 실패할 수 있다 — await findByLabelText 를 쓴다.

ns-multi-select 에 input-invalid 가 생겼다. 안쪽 검색 입력의 aria-invalid 를 세울 통로가 없었다. input-id·input-describedby 와 짝을 맞춘다 — 바로 위 Field 연동이 오류 상태를 내려보낼 때 이 프로퍼티를 쓴다.

breaking — 자식을 받지 않는 래퍼가 타입으로 막힌다

NsPagination·NsMultiSelect·NsSkeleton· PageHeading 넷에 children?: never 를 얹었다. 앞의 둘은 Light DOM 이라 자식이 덮여 런타임 에러가 났고, 뒤의 둘은 슬롯이 없어 조용히 사라졌다 — 문서가 경고하던 것을 컴파일러가 막는다.

타입 수준 변경이고 런타임 동작은 바뀌지 않는다. 오늘 빌드가 통과하는 소비자는 런타임에서 그대로 동작한다. 바뀌는 것은 이미 런타임에서 깨져 있던 마크업 — 예를 들어 <NsPagination>…</NsPagination> — 이 이제 컴파일 시점에 거부된다는 것뿐이다.

v0.5.3

dist/ 변경

ns-header 밑줄이 다시 보인다. 헤더 아래 경계선이 스타일시트에는 있는데 화면에 나오지 않던 것을 고쳤다. 소비자가 할 일은 없다 — 설치하면 선이 돌아온다.

shadow 안의 header 가 box-sizing 없이 height: 100% 를 쓰고 있었다. 문서의 * { box-sizing: border-box } 리셋은 shadow 경계를 넘지 못하므로 그 요소는 CSS 초기값인 content-box 로 시작하고, 밑줄 1px 이 콘텐츠 상자 바깥에 붙어 호스트의 --ns-header-height 를 넘쳤다. 호스트 높이가 고정이라 넘친 1px 은 아래를 밀지 않고, 그 자리에 뒤에 오는 형제의 배경이 트리 순서로 나중에 칠해져 선을 통째로 덮었다.

그래서 셸이 배경색을 가진 소비자에게만 보였다. 이 저장소의 사용 안내는 본문 배경이 투명해 덮을 것이 없었고, 선이 제자리보다 1px 아래에 그려진 채로 계속 보이고 있었다 — 문서 페이지가 결함 있는 상태를 정상으로 보여준 셈이다.

헤더 높이와 본문 위치는 바뀌지 않는다. 넘쳤던 1px 은 원래 레이아웃에 참여하지 않았으므로, 이 릴리스로 움직이는 것은 선 하나뿐이다.

대화상자를 열 때 닫기 버튼에 검정 링이 뜨던 것을 고쳤다. showModal() 이 첫 포커스 가능 자손인 닫기 버튼을 잡고, Chrome 이 그 포커스를 :focus-visible 로 쳐서 링을 그렸다. 밝은 모드의 --ns-color-accent 가 거의 검정이라 테두리처럼 보였다. 이제 초기 포커스가 제목으로 가고 그 요소의 링은 꺼진다.

탭 순서와 접근성은 그대로다. 제목은 탭 순서에 들어가지 않으므로 Tab 은 여전히 닫기 버튼으로 가고, 포커스는 대화상자 안에 머무른다. Safari 에서는 원래 이 링이 없었다 — WebKit 은 모달의 초기 포커스를 :focus-visible 로 치지 않는다.

.ns-card 가 컨테이너 밖으로 넘치던 것을 고쳤다. width: 100% 에 테두리와 안쪽 여백을 얹으면서 box-sizing 이 빠져 있었다 — 같은 파일의 .ns-button·.ns-input 등 나머지 컨트롤은 전부 갖고 있던 속성이 .ns-card 하나만 없었다. * 리셋을 갖지 않은 순수 HTML 소비자에게만 영향이 있었다. Tailwind 를 쓰는 소비자는 preflight 가 box-sizing: border-box 를 전역으로 공급해 이 자리를 대신 메워 줬으므로 아무 증상도 보지 못했다. 소비자가 할 일은 없다 — 설치하면 카드 폭이 컨테이너 안으로 들어온다.

v0.5.2

dist/ 변경

문서를 세 페이지로 나눴다. 지금까지 하나였던 문서가 목차·사용 안내·이 페이지로 갈라졌다. 소비자가 할 일은 없다 — 코드는 주석만 바뀌었다.

이름이 바뀐 파일이 있다. 사용 안내가 index.html 에서 guide.html 로 옮겨갔다. index.html 은 두 페이지로 가는 목차로 남았다 — 그 이름은 우리가 고른 것이 아니라 브라우저가 디렉터리를 받았을 때 찾는 기본 문서라, 없애면 폴더를 여는 경로와 정적 호스팅이 함께 끊긴다. 문서를 index.html 경로로 북마크해 둔 사람은 목차로 도착한다.

v0.4.0 이하의 절을 지웠다. 이 페이지와 README.md 의 릴리스 표가 함께 v0.5.0 부터만 담는다. 태그는 그대로 있다 — v0.2.0~v0.4.0 은 여전히 설치할 수 있고, 문서에서만 뺐다.

dist/ 가 바뀌는 이유는 주석이다. 컴포넌트 스타일이 css 템플릿 리터럴이라 그 안의 주석이 번들에 문자열로 실린다 — 파일 이름을 가리키던 주석들이 guide.html 로 바뀌었다. 화면에 드러나는 변경은 없다.

v0.5.1

dist/ 변경

사이드바를 접을 때 글자가 찌그러지며 리플로우되던 것을 고쳤다. 안쪽 nav 가 --ns-sidebar-width 를 min-width 로 붙들고 :host 가 자르므로, 접히는 동안 내용이 열린 폭 그대로 잘려 사라진다 — 글자가 다시 배치되지 않는다. 그룹 헤딩도 줄바꿈 대신 말줄임표로 잘린다.

그래서 폭을 바꾸는 손잡이는 --ns-sidebar-width 토큰 하나다. ns-sidebar { width: … } 만 따로 덮는 것은 그 값이 토큰보다 좁지 않을 때만 안전하다 — 더 좁게 주면 내용은 여전히 토큰 폭 기준으로 배치된 채 그 좁은 폭에서 잘린다. 이 성질은 위의 min-width 고정에서 그대로 따라 나온다.

v0.5.0

dist/ 변경 · breaking 둘

소비자가 마크업을 고쳐야 하는 것은 하나다.

지금 (0.4.0)바뀐 뒤 (0.5.0)
<ns-sidebar open><ns-sidebar default-open>
<NsSidebar open={x}>그대로 (제어 모드)

<ns-sidebar open> 은 조용히 무시되고 콘솔 경고가 뜬다. open 이 프로퍼티 전용이 되어 관찰되지 않으므로 제어 모드로 들어가지도 않는다 — HTML 에서 초기 상태를 열어 두려면 default-open 이다. React 의 제어 모드(open={x})는 그대로다.

열린 폭은 15rem 그대로다. --ns-sidebar-width 의 뜻도 값도 바뀌지 않았으므로 이주 항목이 아니다(그 토큰이 유일한 손잡이가 된 경위는 v0.5.1 에 있다). 바뀐 것은 닫힌 폭이다 — --ns-sidebar-width-collapsed 가 4rem 에서 0 으로 내려가, 접은 사이드바가 좁은 띠를 남기지 않고 통째로 사라진다.

이 토큰을 덮어 좁은 레일을 되살릴 수는 없다. 값을 올리면 그만큼의 빈 자리가 예약될 뿐 그 안에는 아무것도 그려지지 않는다 — nav 가 통째로 숨으므로 항목도, 제목도, 그 오른쪽 경계선조차 없고 ns-sidebar 의 배경색만 남는다. 이유가 둘이고 서로 독립이다.

  1. 닫힌 사이드바의 내용을 감추는 것은 폭이 아니라 상태다. shadow 안에 :host(:not([data-ns-open])) nav { visibility: hidden } 가 있고, 이 규칙은 닫힘 폭이 얼마든 그대로 걸린다.
  2. 그 규칙이 없더라도 읽히는 띠가 되지 않는다. 0.4.0 에서 좁은 띠에 라벨을 숨기고 항목을 남기던 신호 프로퍼티 둘(--ns-label-display · --ns-group-list-display)이 0.5.0 에 없어졌고 되살리지 않는다. 둘이 없으면 띠에 보이는 것은 15rem 짜리 레이아웃의 왼쪽 끝을 자른 조각 — 잘린 제목과 잘린 라벨 — 이다.

라이브러리가 레일을 다시 주지 않는 이유는 그것을 만들어 보고 물렀기 때문이다. 근거는 docs/gotchas.md 의 레일을 만들었다가 물렀다 에 있다. 레일이 필요한 프로젝트는 사이드바 밖에 자기 칼럼을 두고 이 컴포넌트를 그 오른쪽에 놓는다.

그래서 이 토큰이 정하는 것은 "닫혔을 때 본문을 얼마나 밀어 둘 것인가" 하나다. 접힌 상태에서도 본문이 화면 왼쪽 끝까지 오지 않게 하려면 값을 준다.

닫힌 사이드바는 탭 순서에서도 빠진다. 폭 0 과 overflow: hidden 은 자르는 것이라 그것만으로는 보이지 않는 링크에 Tab 이 내려앉는다. 그래서 폭 전환이 끝나는 200ms 뒤에 안쪽 nav 를 visibility: hidden 으로 숨긴다 — 링크가 탭 순서와 접근성 트리에서 함께 빠지고, 여는 쪽에는 지연이 없어 즉시 보인다. 기대도 되는 보장이다. 딸려 오는 성질이 둘 있다: 닫는 200ms 안에는 아직 Tab 이 닿고, 닫는 순간 사이드바 안에 있던 포커스는 숨김이 도착할 때 <body> 로 떨어진다. 둘 다 "애니메이션 뒤에 숨긴다" 에 내재하는 절충이다.

breaking — ns-nav-item 의 badge 가 없어졌다

배지 사각형은 "접힌 사이드바에서 유일하게 남는 요소" 라는 이유로 있었고, 사이드바가 닫히면 통째로 사라지게 되면서 그 이유가 없어졌다. 속성을 그대로 두면 조용히 무시된다 — 라벨 왼쪽이 비고 그 자리가 접힌다.

대안은 leading 슬롯이다. 원하는 요소를 그대로 넣는다 — 폴백이 아니라 그 자리의 유일한 내용이므로 분기할 것이 없다.

React 도 같다 — badge 프롭 대신 slot="leading" 을 붙인 자식을 넘긴다.

아무것도 넣지 않는 것이 기본이다. 빈 슬롯은 상자도 gap 도 만들지 않으므로 라벨이 왼쪽 끝에 붙는다. 일부 항목에만 leading 을 주면 줄이 들쭉날쭉해 보일 수 있다 — 0.4.0 은 배지가 늘 자리를 차지해 정렬이 강제됐고, 0.5.0 은 그 강제를 놓았다. 한 목록 안에서는 전부 주거나 전부 비우는 쪽을 권한다.

그 밖에

ns-sidebar 밖에서 최상위 ns-nav-group 을 세로로 쌓으면 사이가 24px 좁아진다. 0.4.0 은 첫 형제가 아닌 그룹의 wrapper 에 padding-top: var(--ns-space-6)(24px)을 얹었다. 그 규칙의 :first-child 가 화면과 어긋나게 세는 경우가 있어 지웠고, 남는 것은 헤딩 자신의 padding-top: var(--ns-space-4)(16px)뿐이다. 사이드바 안에서는 보이지 않는 차이지만, 그룹을 평범한 컨테이너에 쌓아 쓰던 소비자는 화면이 좁아진 것을 본다. 되돌리려면 소비자 문서 CSS 한 줄이면 된다 — 호스트는 문서 트리에 있으므로 이 규칙이 shadow 를 이긴다.

ns-nav-group 을 ns-nav-group 안에 중첩하면 하위 카테고리가 된다. 이번 릴리스가 더한 기능이고 breaking 이 아니다 — 새 태그도 새 속성도 없이 그룹이 자기 중첩을 스스로 판정한다. collapsible 은 단을 가리지 않는다 — 최상위 그룹에 붙이면 그 그룹이 통째로 접히고(긴 네비게이션을 줄이는 데는 이쪽이 가장 크다), 하위 그룹에 붙이면 그 카테고리만 접힌다. 0.4.0 마크업에 이미 있는 collapsible 은 옮길 필요가 없다.

새 이벤트는 없다. ns-sidebar 는 자기를 여닫는 버튼을 갖지 않으므로 ns-toggle 을 올리지 않는다 — 헤더의 토글을 받아 사이드바의 open 에 내려주는 배선은 0.4.0 과 같다.
